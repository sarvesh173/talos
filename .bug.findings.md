### ~~LIVE-BUG-1: Session List Clipped Under Floating Search Dock~~ — FALSE ALARM (verified)

* **What actually happens:** Both the agent list and the session list already apply `contentPadding = PaddingValues(top = 96.dp, bottom = 110.dp)`. ### ~~LIVE-BUG-2: System Back Button Triggers Hard App Exit~~ — FALSE ALARM (verified)
* **Location:** `MainActivity.kt:554-575`
* **What actually happens:** A root `BackHandler(enabled = true)` exists and maps `main`/`landing` → `currentActivity?.moveTaskToBack(true)`. That **backgrounds** the task (standard Android "minimize"), it does not kill the activity or lose state.
* **Verdict:** Working as designed. My first read of the symptom was wrong. Keep only as a UX preference note ("no double-back-to-exit confirmation"), not a defect.

### LIVE-BUG-4: Search Field Says "Search agents" but Searches Messages
* **Location:** `ui/LandingScreen.kt:232-239, 409-471, 473-477, 828`
* **Symptom:** Placeholder reads `Search agents`, yet typing fires `client.searchConversations(q)` (232-239). The `searchHits` list renders only inside the `agents.isEmpty()` branch (lines 409-471, nested after line 400), so with ≥1 connected agent on the roster the message hits are never shown; the visible agent list is filtered by name/description (473-477).

### LIVE-BUG-9: Canvas, Diff, Hub, Gallery, Whiteboard, Browser, CLI Manager All Unreachable from UI
* **Location:** `MainActivity.kt:728-751` + `MainActivity.kt:995`
* **Symptom:** Seven full screens cannot be opened by any user action.

The `"whiteboard"` / `"browser"` branches exist at `:904/:910` but are only targeted from `ModuleActivityHub`, which itself is only reachable through the same dead drawer.
* **Impact:** The B2 "fix" in commit `bb59027` is dead code. Feature set advertised in Settings/docs is unreachable in the shipped build.
* **Severity:** High (whole feature areas missing).
* **Evidence:** `grep -n 'appScreen = "' MainActivity.kt` — no assignment of `disabled_chat` or `whiteboard`/`browser` from any live path.

### LIVE-BUG-10: "Draw" Tile Fakes an Attachment Instead of Opening the Whiteboard
* **Location:** `ui/AttachmentSheet.kt:170-172`
* **Symptom:** Tapping **Draw** in the chat attach sheet immediately posts the literal text `"[Whiteboard sketch attached — open the canvas to annotate]"` as a chat message. No canvas/whiteboard opens, and nothing is attached.
* **Root Cause:** `AttachTile("Draw", ...) { onSendText("[Whiteboard sketch attached — open the canvas to annotate]") }`. `WhiteboardSheet` exists (`ui/WhiteboardSheet.kt:53`) but is **never invoked** anywhere in the app.
* **Impact:** User believes a drawing was sent; the agent receives a meaningless string. Same class of defect the media overhaul claimed to have removed.
* **Severity:** High (silent data loss / misleading action).

### LIVE-BUG-12: Biometrics Toggle Enables With No Enrollment Check
* **Location:** `ui/features/SecurityScreen.kt:170-173`
* **Symptom:** Toggling **Require biometrics** flips state immediately and silently, even when the device has no enrolled biometric. No system enrollment prompt, no error, no explanation. Verified live: switch turned on, and `Instance tokens & keys` flipped `Covered` → `Protected` with no authentication step at all.
* **Root Cause:** `onCheckedChange = { client.setRequireBiometrics(it) }` — a bare preference write. `isBiometricAvailable(activity)` exists in `ui/entry/AppLockPrompt.kt:255` but is never called by this screen.
* **Impact:** Lock can be enabled on hardware that cannot satisfy it; the user only discovers it at the lock screen.
* **Severity:** High (potential lockout path).

### LIVE-BUG-13: "Chat" Button on the Root Screen Is a Permanent No-Op
* **Location:** `ui/LandingScreen.kt:720-737`
* **Symptom:** The top-left **Chat** button on the Agents root is tappable (bounds `[53,96][181,222]`, `clickable=true`) but does nothing. Verified: UI tree hash identical before/after the tap.
* **Root Cause:** `clickable { selectedAgent?.let { openChat(it, "Active conversation") } }`. On the root screen nothing is selected, so `selectedAgent` is `null` and the lambda never runs. The same label only becomes functional ("Back") after a selection, i.e. exactly when the button's purpose changes.
* **Severity:** Medium (dead primary affordance).

### LIVE-BUG-17: Every App-Created Session Is Titled "New Session"
* **Location:** `ui/chat/RemoteSession.kt:143-148`
* **Symptom:** On **Past sessions**, three different sessions all read `New Session` with only a relative time to tell them apart. The list is unusable.

### LIVE-BUG-18: Blank Session Id Mints a Random Room and Abandons `the-council`
* **Location:** `ui/AppleAgentChatScreen.kt:422-430`, `network/TalosClient.kt:594`
* **Symptom:** Opening chat without a chosen session (e.g. the `chat` deep-link route, which passes `activeSessionId = ""`) switches the client onto a freshly generated random room.
* **Root Cause:** `activeSessionId.ifBlank { "ses_" + UUID.randomUUID()… }.let { client.switchRoom(it) }`. `_currentRoomId` defaults to `"the-council"` and `switchRoom` only writes the new id into memory — it is never persisted — so the default room and its cached messages are dropped, and each fresh entry can mint another orphan room on the host.
* **Severity:** Medium (orphan rooms accumulate; history looks empty).
